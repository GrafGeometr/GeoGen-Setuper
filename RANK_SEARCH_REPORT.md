# Ранговый интервал: реализация и испытания

18 ноября 2026. Реализация для ветки feature/family-discovery.

Реализован точный локальный отбор следующих построений по долям отсортированного
списка. Работоспособность отбора проверена. Улучшение качества найденных задач
в этих испытаниях не получено: профиль без отбора дал больше результатов после
Extending, чем два проверенных ранговых профиля.

## Что выполняется в C#

Для текущей конфигурации P:

1. Штатный ConfigurationGenerator перечисляет все следующие определения.
   Сохраняются бюджеты типов, HiddenPoints, исключение повторных определений
   и выбранный канонический фильтр GeoGen.
2. SymmetryReachability отбрасывает варианты, которые нельзя достроить
   до требуемой симметрии. Это исходная проверка, вынесенная в общий метод;
   координаты для отвергнутых вариантов не считаются.
3. Для каждого оставшегося варианта клонируются координаты P и выполняется
   построение. Невозможные построения, совпадения с объектами P и
   несовместимые численные картинки исключаются.
4. Штатный FindNewTheorems находит новые утверждения. Старые утверждения,
   ставшие недействительными, удаляются. При необходимости проверяется
   minimumNewTheorems. Прувер на этом этапе не вызывается.
5. Получается число s: по умолчанию s = T/N, где T — число различных
   утверждений полной конфигурации, N — число именованных точек.
   Альтернатива newPointTheorems считает утверждения с добавленной точкой.
   При явно заданных весах считаются суммы весов.
6. Полный допустимый список сортируется по s по возрастанию, при равенстве —
   по исходному порядку. Из M вариантов оставляются индексы
   floor(from*M) ... ceil(to*M)-1. Выбранные определения поступают
   в обычный DFS в исходном порядке.

В памяти просмотра находятся определения и оценки. Координаты всех вариантов
не сохраняются. Для выбранных вариантов штатный verifier повторно выполняет
построение и FindNewTheorems; это дополнительная цена текущей реализации.
Родительские кэши DFS при предварительном просмотре не меняются.
Сортировка занимает O(M log M), хранимый список — O(M); главная вычислительная
работа — канонизация, координаты и поиск теорем для всех детей.

Ограничений «посмотреть 16, оставить 4» здесь нет. Не используется и targetRatio.
При [0,1] и minimumNewTheorems=0 предварительного просмотра нет вообще.
При этом keepOutsideTargetsPercent=100 отключает прежний отдельный пороговый
отбор. Получается обычная генерация GeoGen.

rankIntervals задаёт интервал на каждом добавлении объекта, последняя запись
повторяется. finalRankInterval заменяет запись на последнем шаге, допускаемом
лимитом итераций и суммарным бюджетом добавляемых типов объектов.
Примеры и команды: [RANK_SEARCH.md](RANK_SEARCH.md).

## Симметрия и остановка

OnlySymmetric/OnlyFullySymmetric сохраняют раннюю проверку достижимости
симметрии и штатные требования к выдаваемым конфигурациям. Ранговый список
содержит также временно асимметричные продолжения, которые можно достроить.
Частичный интервал может их удалить и потерять соответствующие симметричные
задачи. Ранжирования целых симметричных блоков здесь нет.

Если время истекло в середине просмотра, неполный список не выдаётся за полный:
пул записывается с complete=false и поиск завершается. MaxEvaluated учитывает
оба вида вызовов finder. Проверка времени выполняется между кандидатами;
один долгий вызов канонизации или прувера может выйти за внутренний лимит.

существующий поток проверок; обращений из C# в Python при ранжировании нет.

## Проверки

- 289 тестов решения C# прошли, включая 25 новых случаев рангового отбора.
- 94 теста Python-обвязки прошли.
- Полный интервал проверен для трёх режимов симметрии и двух фильтров
  Fast/MemoryEfficient: совпали порядок результатов, теоремы и число
  вызовов конструктора/finder с обычной генерацией.
- Проверены реальные оценки после построения, равные оценки и округление,
  независимые интервалы шагов, finalRankInterval, minimumNewTheorems,
  HiddenPoints, достижимость симметрии и прерванный предварительный просмотр.
- Для стартовой картинки из семи точек просмотрен весь допустимый список
  из 20 продолжений; средний интервал оставил 10. Результат сравнивался
  со штатным генератором, а не с константой числа предложений.
- При двух уровнях DFS инкрементальные карты теорем после отбора сравнивались
  с полным FindAllTheorems для полученных картинок.

Сборка из чистых закреплённых исходников с последовательным применением всех
16 патчей прошла с --test: 289 тестов C#, regression Extending, сборка Geometry
и конвертера, полный smoke GeoGen → конвертер → .geo/Extending/кампания.
Все 364 C#-исходника совпали с деревом, использованным для длительных запусков.
В готовом комплекте дополнительно выполнен 20-секундный ранговый запуск:
1676 вызовов finder при просмотре, 6 завершённых пулов и 2 факта в потоке
без Extending (--no-check). Doctor подтвердил наличие компонентов;
интерактивное GUI в этой сессии не проверялось.

Используется установленный и закэшированный инструментальный набор; установку
пакетов на пустой ОС этот прогон не проверяет. Итоговый журнал и smoke входят
в архив испытаний.

## Три запуска по 600 секунд

Одинаковый story incircle-symmetric.txt: A,B,C и три точки касания вписанной
окружности; 11 допустимых построений; ещё до четырёх точек;
GenerateOnlySymmetric. Seed=61, фактически три численные картинки.
Сам срез при фиксированных оценках детерминирован. Seed в policy=soft
не фиксирует штатные случайные координаты начальной картинки; битовая
повторяемость запусков здесь не обеспечена.
Extending: один worker, лимит 2000 мс на проверку; включены standard-checks
и quality-checks. Исходные конфигурации, JSON и журналы сохранены.

Три процесса работали одновременно в контейнере с общей квотой 2 CPU и 8 GiB
памяти. Это сравнение при совместной нагрузке, а не замер производительности
на выделенном компьютере. Один сюжет и один seed не являются подбором
оптимального профиля или репрезентативной оценкой качества генератора.

Последний профиль: на первых шагах верхняя половина по T/N, на последнем —
нижняя половина по newPointTheorems с minimumNewTheorems=1. Это самостоятельное
ограничение, поэтому последний столбец не изолирует влияние одного интервала.
У средней политики завершены 125 из 126 пулов, у последней — 73 из 74;
последние незавершённые пулы остановлены по времени. Максимальные завершённые
списки содержали соответственно 779 и 819 вариантов.

ready здесь означает, что задача прошла реализованные проверки. Все 20 таких
результатов получили sampled-valid на восьми численных примерах каждый.
Это не сертификат сложности, не доказательство новизны и не математическое
доказательство утверждения. Таймауты нельзя считать ни отклонением, ни успехом.

## Что следует из результатов

Точный ранговый механизм работает и позволяет выражать предпочтение понятной
долей текущего списка. Полный интервал сохраняет исходный путь без цены
предварительного просмотра. Частичные интервалы действительно меняют
исследуемые ветви, но в этих запусках не дали улучшения результата.

Средний интервал потратил около 91% времени на просмотр и выдал первый факт
только через шесть минут. Поэтому узкий интервал не означает дешёвый поиск:
полную цену просмотра приходится платить до выбора даже одного продолжения.
Число теорем само по себе также не гарантирует, что выбранные факты будут
содержательнее. Подтверждений задач уровня IMO-6 этими испытаниями нет.
