# Технический отчёт: условный Extending, 2026-11-19

## Что выполняет код

Добавлен C#-модуль `ConditionalExtender`. Он получает исходную конфигурацию,
одну дополнительную посылку и заключение. По очереди меняется одно определение;
все последующие объекты пересчитываются штатными конструкторами GeoGen.

`ConditionalWeakeningCatalog` содержит 136 альтернатив для 72 построений,
соответствующих Haskell `Functions.functions`. Три построения имеют ноль
альтернатив, как и раньше: NinePointCircle, ReflectionInLine, TangentLine.
Во время сборки C# и Haskell экспортируют каталоги; несовпадение останавливает
сборку. На обычных и условных исходных картинках дополнительно проверяется,
что предлагаемый ослабленный объект допускает исходное определение.

Общий `ConditionalSampler` теперь умеет работать с дополнительными свободными
параметрами. A=(0,0), B=(1,0), C=(x,y). При ослаблении добавляются:

| Ослабление | Свободные параметры | Размерность спуска |
|---|---|---:|
| Точка на прямой | Подписанное расстояние вдоль прямой | 3 |
| Точка на окружности | Полярный угол | 3 |
| Произвольная точка | Две координаты | 4 |
| Прямая через точку | Направление | 3 |
| Прямая заданного направления | Смещение | 3 |
| Окружность с заданным центром | Радиус | 3 |
| Окружность через заданную точку | Координаты центра | 4 |
| Центр окружности на прямой, заданная точка/касательная | Положение центра | 3 |

Нельзя случайно оставить ослабленную точку фиксированной: её параметры входят
в тот же вектор спуска, что и x,y. Невязка прежней дополнительной посылки
вычисляется на заново построенной картинке. Используется прежний алгоритм:
центральные разности h=10⁻⁵, шаг −f∇f/(||∇f||²+10⁻¹²), ограничение длины 0.4,
деление шага пополам при отсутствии улучшения. Принятие корня: |f|<10⁻¹²,
регулярный градиент и невырожденные объекты. По умолчанию до 80 стартов и
60 шагов на старт. Геометрия и оптимизация работают внутри одного C#-процесса.

## Правила принятия решения

Сначала независимо проверяется исходная условная задача: восемь картинок с
посылкой, заключение на всех них и минимум два контрпримера без посылки
среди до 12 обычных картинок. После этого проверяются ослабления.

- Один допустимый контрпример с |невязка заключения|>10⁻⁵ опровергает
  конкретное обобщение. Дальнейший подбор для него не нужен.
- Если заключение сохраняется, требуются две серии по восемь картинок с
  разными seed. Невязка заключения должна быть ≤2·10⁻⁸. Как минимум две
  поддерживающие обобщение картинки должны действительно нарушать заменённое
  определение. Только после этого задача получает `rejected`.
- Для `accepted` нужны контрпримеры ко всем альтернативам каталога.
  Непроверенное ослабление не считается пройденным.
- Недостаток картинок, неопределённый вспомогательный локус или промежуточная
  невязка дают `inconclusive` → `review`. Общий таймаут остаётся `timeout`.
- Новые корни также проверяются в исходной конфигурации. Если обнаружен
  контрпример к ней самой, результат — `counterexample`, а не успешное
  прохождение фильтра ослаблений.

`--check-ms` — общий бюджет исходной проверки и всех ослаблений. Дополнительно
есть бюджет одного варианта: max(250, min(2000, check-ms / число вариантов)) мс.
Неопределённое ослабление можно пропустить и проверить следующее: найденное
в другом месте обобщение всё равно достаточно для отбраковки. Без обобщения
остаточные неопределённые варианты препятствуют успешной проверке.

## Подключение

Поток `run` и семейные кампании используют новый маршрут автоматически для
задач с `condition`. JSON-ответ только о восьми исходных картинках не принимается
за полную проверку: проверяются статус и полнота списка ослаблений.

Сам Haskell Extending распознаёт `!Assume:` в одиночном и каталоговом режимах
и один раз вызывает C#-модуль. Прямой `--check-file` не переименовывает вход.
Каталоговый режим и `geometry-suite check` помечают решённые отбраковки BAD_.
Старый `--validate-file` для условного файла возвращает явный неопределённый
результат, чтобы не проверять заключение без посылки.

Вычислений через Haskell/Python на каждой итерации нет. Python ведёт очередь;
Haskell остаётся обычным проверяющим модулем для задач без дополнительных
условий. Отчёт `condition-check.json` содержит конкретное заменённое построение,
вариант, размерность, свободные координаты, невязки и покрытие проверок.
`changedDefinitionSamples` относится к пробам, поддерживающим обобщение.

## Проверки

- Чистая сборка закреплённых исходников с 23 патчами завершена, включая smoke.
- 382 C#-теста прошли. Проверено включение оригинала во все 136 альтернатив
  на трёх независимых обычных картинках: 408 проверок. Есть тесты для пересчёта
  последующих объектов, сохранения необходимого определения, нахождения
  лишнего определения, отсутствия допустимых картинок и вырожденного
  вспомогательного локуса.
- 113 Python-тестов прошли. Проверены невозможность подменить покрытие
  ослаблений одной проверкой истинности, неполное покрытие, статусы очереди,
  отчёты качества и переименование только решённых отбраковок.
- Haskell regression прошёл. Каталоги совпали: 72 имени, 136 альтернатив.
- Прямой Haskell `--check-file` принял контроль с необходимой серединой и
  отверг контроль с лишним определением O. Проверены пробелы в имени файла,
  комментарии `!Assume:`, охрана обычного валидатора и каталоговое BAD_.
- Отдельно проверены условные ослабления окружности, прямой и точки на
  окружности. Все необходимые определения сохранились.
- Две реальные находки прошли всю очередь: одна получила `rejected`, другая
  `ready` с полным покрытием 12 ослаблений. Готовый чертёж проверен Geometry.

Контроль на отбраковку: ABC, O — центр описанной окружности, H — ортоцентр;
добавлено AB=AC, заключение A,O,H коллинеарны. Достаточно заменить O
произвольной точкой серединного перпендикуляра к BC — заключение сохраняется
на 16 разных картинках, в том числе с нарушенным исходным определением O.

Контроль необходимого определения: D — середина AB; добавлено AD=CD;
заключение AB:CD=2:1. После замены D произвольной точкой AB при прежнем
условии находятся контрпримеры. Этот контроль проверяет корректность механизма,
а не сложность задачи.

## Реальные данные

Перепроверены 50 задач из предыдущего запуска с шестью исходными точками
(A,B,C,O,H,I) и ещё одной построенной точкой. Все они были `ready` после
прежней условной проверки. Выбрано по десять задач для каждого из пяти типов
посылки, распределённых по порядку нахождения. Два рабочих процесса,
5000 мс на задачу:

| Результат | Число |
|---|---:|
| Найдено обобщение (`rejected`) | 49 |
| Контрпримеры ко всем ослаблениям (`accepted`) | 1 |
| Неопределённость / таймаут / ошибка | 0 |

Повторный запуск окончательной версии занял 11.160 с. Это перепроверка 50
сохранённых задач, а не новый длительный генерационный эксперимент.
Выборка ограничена тремя конечными конфигурациями предыдущего поиска;
переносить долю отбраковок на произвольные сюжеты нельзя.

Прошедший контроль всех 12 ослаблений пример:

```text
Triangle: A, B, C
D = Circumcenter(A, B, C)
E = Orthocenter(A, B, C)
F = Incenter(A, B, C)
G = PerpendicularProjectionOnLineFromPoints(A, B, E)
Assume: ConcyclicPoints: A, E, F, G
Goal: PerpendicularLines: [A, E], [D, F]
```

Прохождение каталога не устанавливает сложность, новизну или отсутствие других
обобщений. Дополнительная посылка может иметь несколько компонент решений;
конечные численные пробы не гарантируют их полный охват. Сфера первой версии
прежняя: Triangle и ограниченная область нормированных координат.
