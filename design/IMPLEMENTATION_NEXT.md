# План реализации: управляемое построение и численные дополнительные условия

18 ноября 2026. Уточнение после замечаний пользователя. Это план изменений
продукта; выполненный численный эксперимент описан отдельно. C#-код новых
механизмов ещё не написан.

Следующее уточнение: [SOLVERS_AND_RELATIONS.md](SOLVERS_AND_RELATIONS.md).
Оно заменяет скалярную долю непрозрачных объектов профилями конкретных
отношений, добавляет распознавание эквивалентных определений и содержит
сравнение численных решателей. Первый backend уточнён до Брент + dogbox/Gauss–Newton.

## Что меняется по сравнению с предыдущими проектами

1. Баланс понятной геометрии и непрозрачных объектов управляет предложением
   следующего построения до полного построения/анализа чертежа. Перечисление
   всех сочетаний с последующей оценкой не считается выполнением задачи.
2. Примеры форм задач не превращаются в обязательные шаблоны. Выбирать можно
   любое разрешённое построение; политика управляет выбором операции и аргументов.
3. Основной способ получить картинки при дополнительном условии — численный
   поиск по функции, вычисляющей построения. Развёрнутые символьные выражения,
   факторизация и геометрическая параметризация для него не требуются.
4. Ограничение первой версии только рациональными построениями отменяется.
   Существующие радикальные построения вычисляются тем же прямым способом,
   пока определены и достаточно устойчивы. Новая проблема — обусловленность
   и ветви, а не размер развёрнутого многочлена.

## А. Генератор с управлением до построения

### Хранимое состояние

Граф определений; небольшой набор разведочных картинок; профиль объяснимых
зависимостей объектов и направлений; существенные ещё плохо объяснённые
объекты; стоимость/глубина; очередь продолжений; происхождение находок.
Профиль опирается на поддержанные локальные правила и их ограниченное замыкание.
Неизвестные модулю построения помечаются отдельно от геометрически непрозрачных.

Это не число «всех зависимостей». Для каждой используемой теории учитываются
объяснимость относительно других объектов, простые способы исключения и
связи между группами. Предыдущие численные находки не становятся бесплатными
аксиомами заключительного оценщика задачи.

### Шаг поиска

1. По текущему профилю выбрать режим действия: усилить объяснимые связи;
   добавить объект с плохо связанными аргументами; исследовать связь уже
   непрозрачных объектов с остальным рисунком. Поддерживать несколько целевых
   уровней непрозрачности, чтобы одна гипотеза о хорошей пропорции не заперла поиск.
2. Сэмплировать, например, 24 конкретных допустимых действия. Сначала операция
   из каталога, затем аргументы нужных типов с весами из профиля. Известные
   близкие и слабосвязанные аргументы выбираются разными распределениями.
   Совпадения/симметрии аргументов нормализуются. Все n^k сочетаний не создаются.
3. Дешёво оценить действие по аргументам, свойствам операции, полной стоимости
   и прогнозу изменения профиля. Для лучших нескольких построить объект на
   небольшой разведочной выборке; проверить определённость и обновить профиль.
   Это ограниченная проба немногих действий, а не полный finder для всех кандидатов.
4. Сохранить несколько разнородных продолжений. Для выбранных состояний
   запустить поиск новых фактов и глубокую проверку найденных утверждений.
   После добавления непрозрачного объекта выделять бюджет на его участие
   в новых целях: бесполезные странные точки не считаются успехом.
5. Результаты потомков обновляют предпочтения сочетаний «операция — тип
   аргументов — состояние». Ценность приносит подтверждённая существенная
   связь, пережившая сокращение и дедупликацию; начисление отложено до проверки.

Числа 24/размер разведочной выборки — начальные параметры опыта, не установленный
оптимум. Протокол измеряет отдельно число сэмплированных действий, реально
построенных объектов, запусков finder и стоимости проверок.

Состояние без немедленного факта может получить ещё несколько шагов.
При избытке непрозрачных объектов политика чаще усиливает основу или ищет
связи; при полностью объяснимом рисунке — чаще вводит новые смешанные объекты.
Это регулятор действий в процессе генерации, а не фильтр готовой выдачи.

### Изменения в коде

- В `ConfigurationGenerator.cs` выделить прямую генерацию небольшого набора
  действий по сигнатурам вместо вызова полного `Variations` для нового режима.
  Обычный DFS оставить отдельной стратегией для совместимости и сравнения.
- В `ProblemGenerator.cs` выделить состояние с собственными pictures/context/facts.
  Убрать зависимость нового режима от глубины общего стека. Одно действие
  достраивается через существующий `ConstructByCloning`.
- Дополнить каталог сигнатур раскрытыми графами примитивов и локальными
  свойствами. Переиспользовать `ITrivialTheoremProducer` и существующие
  стандартные reasoner-модули для поддержанных объяснений.
- Python-модуль профиля импортирует `standard_reasoning.py`, кэширует родителей
  и обрабатывает приращения. Предложения передаются C#-worker пакетами,
  без запуска Python-процесса на каждое построение/численное вычисление.
- C#-worker возвращает приращение наблюдений напрямую из finder. Старый
  GeneratedProblemAnalyzer не должен заранее выбросить результат лишь как
  простое следствие OldTheorems, принятых за уже доказанные гипотезы.

## Б. Дополнительное условие как вычисляемая функция

### Прямой вычислитель

Для треугольника выбрать A=(0,0), B=(1,0), C=(u,v). Для обычных задач,
инвариантных относительно подобия, достаточно менять u,v. Для четырёхугольника
нужны четыре параметра. Ограниченные исходные базы имеют собственные
параметризации. Ориентация/область допустимости задаются явно.

`ConfigurationEvaluator` принимает вектор параметров, вызывает существующий
`IGeometryConstructor.Construct(..., looseObjectConstructor)` и получает
значения нужных объектов. Для невязки вычислять только предков объектов
дополнительного условия. Ни TheoremFinder, ни ContextualPicture со всеми
неявными окружностями в этом внутреннем цикле не нужны.

Схема вычислений и зависимости компилируются/кэшируются один раз. При смене
вершин численные значения пересчитываются. Размер памяти определяется графом
построений, а не размером раскрытого символьного выражения.

### Численные невязки

Добавить `PredicateResidual`, возвращающий непрерывное число/вектор вместо
булева IsTrue. Первая версия: параллельность, перпендикулярность,
коллинеарность, равенство отрезков; затем вписанность.

- Параллельность: нормированное векторное произведение направлений.
- Перпендикулярность: нормированное скалярное произведение.
- Коллинеарность: ориентированная площадь, нормированная на квадрат масштаба.
- Равенство отрезков: разность квадратов длин с нормировкой масштаба.

Проверять ненулевые направления, допустимость построений, совпадения,
исходные ограничения. Для параллельности явно сохранять требование разных
прямых: нулевой угол между совпадающими прямыми недостаточен.
Не заменять ошибку построения нулевой невязкой. Согласовывать знак направления
между близкими вычислениями, чтобы нормализация Line не ломала производные.

### Получение первого решения

`ConditionSampler` использует несколько независимых стартов и демпфированный
Newton/least-squares с trust region. Якобиан сначала считать конечными
разностями: свободных параметров мало, переписывать все конструкторы под
автоматическое дифференцирование не требуется. QR/SVD использовать через
зафиксированную .NET-библиотеку линейной алгебры, например MathNet.Numerics.

Один шаг: построить геометрию, получить невязки, оценить производные,
вычислить ограниченную поправку параметров, проверить новую геометрию.
При неудаче уменьшить шаг или сменить старт. Пределы итераций, вычислений
и общего времени обязательны. Неудача означает unresolved, не отсутствие решений.

### Много разных картинок

После решения найти касательное направление из ядра якобиана. Сделать шаг
вдоль него и исправить уход от условия небольшим корректором. Для скалярного
условия и двух параметров добавить корректору условие поперечного сечения,
чтобы он не возвращался в ту же точку. Менять направление/размер шага.

Независимые старты искать отдельно от траекторий продолжения: соседние точки
одной траектории не выдаются за независимые проверки всех ветвей.
Хранить параметрические координаты, seed, маркеры ветвей/обусловленности,
минимальные расстояния, невязки и причину отказа. Маленькие ограниченные
области координат — только поисковые окна; несколько окон расширяют охват.

При добавлении условия пересобирать набор картинок под ним. Картинки
обычного родителя в общем случае этому условию не удовлетворяют.

### Контроль повышенной точностью

Текущий движок C# считает double. Старый exact Haskell-checker нельзя
использовать как будто округлённые корни точно выполняют новое условие.

Сделать отдельный `conditional_verify.py`: интерпретатор экспортированного
графа примитивов на mpmath с 80/160 знаками. Реализовать небольшой существующий
набор примитивов (линия, окружность, пересечение, проекция, биссектриса,
отражение, гомотетия и т. п.); составные построения раскрываются в этот граф.
Доставить зафиксированную pure-Python-зависимость вместе с комплектом.

На контрольных независимых стартах уточнять корни при высокой точности,
заново вычислять цель, проверять устойчивость при увеличении точности и искать
контрпримеры. Примитивы сверять с C# и Haskell на поддержанных обычных входах.
Неэкспортируемое построение получает явный unsupported, не успешную проверку.

Это численное подтверждение кандидата, не доказательство полноты ветвей
и не символическое доказательство теоремы. Полные интервальные/алгебраические
сертификаты — отдельный следующий уровень, не предпосылка запуска поиска.

## В. Поиск задач на условных картинках

Ввести `ResearchProblem`: определения, исходная область, дополнительные
предпосылки, цель. Предпосылки входят в ключ задачи, прувер и отображение.
Обычные story сохраняют прежнюю семантику; новый синтаксис не появляется молча.

Генератор выбирает ограниченную порцию предпосылок по слабо объяснённым
отношениям, получает условные картинки и ищет на них новые факты.
Один набор условных картинок используется для множества целей и продолжений.
Прямые следствия предпосылки отсеивают condition-aware стандартные reasoners.
Сравнение с обычными картинками выявляет цели, которым условие действительно нужно.

В первом условном режиме старый Extending не запускается с прежним смыслом:
его случайные картинки условие не сохраняют. Он либо получает адаптер
к новому sampler, либо результат явно отмечается «обобщения этим методом
ещё не проверены». Согласованное ослабление требует сохранять новую предпосылку
и проверять включение исходного семейства в ослабленное. Это самостоятельная
работа, которую нельзя спрятать под сменой флага команды.

## Г. Узлы реализации и границы процессов

| Узел | Размещение | Контракт |
|---|---|---|
| ConfigurationEvaluator | C# рядом с Constructor | Параметры базы → значения нужного подграфа, статус допустимости |
| PredicateResidual | C# | Значения объектов → нормированные невязки и условия определённости |
| ConditionSampler | C# | Предпосылки и бюджет → набор условных картинок или причины неудачи |
| ActionSampler | C# рядом с ConfigurationGenerator | Состояние, веса, seed, лимит → небольшой набор разрешённых действий |
| ResearchWorker | Новый долгоживущий launcher C# | Инициализация, пакет действий, раскрытие, условные картинки; JSON-протокол |
| research.py / profile.py | Python рядом с discovery | Профиль, политика действий, очередь, SQLite, учёт затрат и обратной связи |
| conditional_verify.py | Python | Независимое уточнение условных картинок и целей на высокой точности |

Внутренние численные итерации целиком проходят внутри worker: IPC
не выполняется на каждое вычисление невязки/производной. SQLite хранит
постоянное состояние, worker — ограниченный LRU картинок. Восстановление
по сохранённым исходным параметрам и определениям, без сериализации CLR-объектов.
Штатная сборка получает новые файлы через проверяемые патчи и копирование модулей.

## Д. Результаты численного опыта

Отдельный Python-прототип, не полный GeoGen. Никаких символьных уравнений
не строилось. A=(0,0), B=(1,0), C=(u,v), окно u∈[-0.7,1.7], v∈[0.16,2.2].
Для каждого условия 64 старта; производные конечными разностями.

1. Прямая Эйлера параллельна A-симедиане: 64 сходимости. Все найденные
   решения дают совпадение этих прямых; строгую параллельность они не подтверждают.
   Это полезный контроль семантики/вырождений, не доказательство отсутствия
   других решений численным методом.
2. Прямая Эйлера перпендикулярна A-симедиане: 52 сходимости, 12 unresolved;
   11 точек на одной траектории продолжения; около 0.44 секунды.
3. Смешанная цепочка: I — инцентр; J=mid(B,H); K — проекция C на AI;
   D — проекция I на JK. Условие: AD параллельна прямой Эйлера.
   38 сходимостей, 26 unresolved; 30 точек продолжения; около 0.82 секунды.

Максимальная нормированная невязка третьего опыта около 2.8e-12.
В каждом опыте пять решений уточнены отдельно при 80 знаках, с другой
формулой вычисления прямой Эйлера; невязки порядка 1e-80.

Опыт показывает осуществимость вычисления условных картинок с радикальными
построениями. Не проверяет все компоненты, не доказывает теорем и не обещает
такого времени для длинных плохо обусловленных построений. Полные проверки
дубликатов всех объектов ещё должны выполняться продуктовым конструктором.
Исходник, журнал и результаты: work/numerical-conditions-2026-11-18/.

## Е. Порядок работ и проверяемые результаты

1. **Evaluator + residual + sampler.** Результат: для заданных построений и
   одной предпосылки worker возвращает разные допустимые картинки, затраты
   и явные причины отказа. Контроли: примеры выше, невозможное условие,
   совпадающие прямые, почти равносторонний треугольник, разные ветви.
2. **Прямое предложение действий + профиль.** Результат: для одного состояния
   выбирается ограниченная порция построений с объяснимыми аргументами.
   Ни один счётчик не показывает полного обхода всех сочетаний. Контроль:
   при изменении профиля меняется распределение предлагаемых действий.
3. **Динамическая исследовательская сессия.** Результат: несколько поколений
   состояний, поддержание разных уровней непрозрачности, участие новых объектов
   в существенных целях, продолжение после прерывания. Контроль: стандартный
   промежуточный факт не закрывает всех потомков, награда приходит после проверки.
4. **Условные задачи end-to-end.** Результат: автоматически предложенная
   предпосылка → условные картинки → новые цели → независимая проверка →
   Geometry с видимым дополнительным условием. Подключить точные поддержанные
   reasoners с предпосылками и высокую точность для численных кандидатов.
5. **Сравнение и калибровка политики.** Равные полные CPU-бюджеты для нынешнего
   генератора, ограниченной случайной политики и политики с профилем.
   Учитывать все предварительные вычисления. Мерить существенные уникальные
   кандидаты за время, стоимость одного результата, долю простых следствий,
   контрпримеры и разнообразие. Человеческую сложность оценить слепой выборкой;
   без неё доказуемы только технические улучшения, не рост качества «для человека».

Первые четыре пункта дают конкретные исполняемые механизмы. Если пятый
не показывает преимущества политики перед случайным ограниченным поиском,
пересматривать профиль/выбор действий; успешная интеграция сама по себе
не считается качественным скачком.
