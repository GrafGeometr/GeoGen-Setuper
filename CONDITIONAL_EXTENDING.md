# Extending с дополнительным условием

Условные задачи теперь проходят проверку ослаблений. Режим включается автоматически
для событий с полем `condition` и для `.geo` с комментарием `!Assume:`.
Обычные задачи по-прежнему проверяет прежний Haskell-код.

## Запуск

Соберите обновлённый сборщик, сохранив старый комплект:

```bash
bash build.sh build --output ./dist/geometry-suite-conditional-extending --jobs 2 --test
```

Если инструменты уже установлены в другом каталоге, добавьте
`--state /абсолютный/путь/к/старому/GeoGen-Setuper/.builder`.
Локальный архив этой версии: `GeoGen-Setuper-conditional-extending.tar.gz`;
он распаковывается в `GeoGen-Setuper-conditional-extending`.

Команда поиска прежняя:

```bash
./dist/geometry-suite-conditional-extending/geometry-suite run ./stories/hard.txt \
  --conditions-config ./conditions.json --output ./runs/conditional-extending-001 \
  --workers 2 --check-ms 5000 --timeout 660 --standard-checks --quality-checks --view
```

`--check-ms` теперь покрывает повторную проверку исходной условной задачи и
проверку всех ослаблений. Если времени недостаточно, будет `timeout` либо
`review`, а не успешная проверка. Для сложных входов можно увеличить его
до 15000–30000. `--no-check` по-прежнему отключает Extending.
Отдельный `audit` проверяет истинность и рисунки; он не заменяет Extending.

Проверка сохранённых файлов:

```bash
./dist/geometry-suite-conditional-extending/geometry-suite check ./runs/old/geo --timeout 15
```

Для условных файлов это до 15 секунд на файл. Результаты записываются
в `extending-report.json`; решённые отбраковки получают префикс `BAD_`.
Команда `check` не переписывает статусы старой очереди `tasks.sqlite`.
Одиночный вызов самого Extending не меняет имя файла:

```bash
./dist/geometry-suite-conditional-extending/lib/extending/GeometryExtending \
  --check-file ./example.geo 5000
```

## Алгоритм

1. В исходной конфигурации независимо находятся восемь регулярных картинок,
   где выполнено условие, и два контрпримера без него. Проверяется заключение.
2. По очереди выбирается одно построение и один вариант его ослабления из
   каталога Extending. Остальные определения сохраняются; все последующие
   объекты пересчитываются после замены.
3. Ослабленное определение параметризуется. У точки на прямой одна свободная
   координата, у произвольной точки две, у точки на окружности один угол,
   у прямой через точку одно направление и т. д. К параметрам формы
   выбранного старта добавляются параметры ослабленного объекта.
4. С прежней дополнительной посылкой ищутся картинки ослабленной конфигурации.
   Если заключение нарушается с нормированной невязкой больше 10⁻⁵,
   это ослабление не обобщает задачу; поиск следующего начинается сразу.
5. Если заключение сохраняется, проверяются две серии по восемь картинок
   с разными seed. Для подтверждения обобщения требуются как минимум две
   картинки, где заменённое определение действительно нарушено. Тогда задача
   отбраковывается: полное определение выбранного объекта оказалось лишним.
6. Если для каждого варианта найден контрпример, задача проходит каталог
   Extending. Если какой-то вариант остался без достаточного числа допустимых
   картинок, успешная проверка не выставляется. Один найденный вариант
   обобщения достаточен для отбраковки; остальные можно не проверять.

Для каждого ослабления сначала проверяется, что оно допускает исходное
построение на обычных и условных картинках. Несоответствие каталога даёт ошибку.
Также новые картинки проверяются на контрпример к исходной задаче: спуск
может обнаружить ранее пропущенную ветвь решений посылки.

Общий срок проверки дополняется ограничением времени на один вариант, чтобы
трудный подбор не занимал весь бюджет. Неудача подбора означает неопределённый
результат, а не опровержение или доказательство обобщения.

## Реализация и покрытие

Все численные пересчёты, спуск, ослабления и проверка заключения выполняются
в C#. Haskell при наличии `!Assume:` один раз запускает этот модуль; обмена
между языками на каждом шаге спуска нет. Python ведёт очередь и хранит JSON.

Перенесены все 136 альтернатив для 72 построений из Haskell-каталога.
`NinePointCircle`, `ReflectionInLine` и `TangentLine` в исходном Extending
не имеют альтернатив; это явно отражено в отчёте. Во время сборки каталоги
C# и Haskell сравниваются по именам и числу вариантов. Дополнительно тесты
проверяют включение исходного объекта в каждое ослабление на независимых
обычных картинках.

Основные файлы: `ConditionalWeakening.cs`, `ConditionalSampler.cs`,
`ConditionalExtender.cs` и `ConditionalExtendingCommand.cs`. Сборщик добавляет
два патча поверх условного поиска, всего 23 патча. Проверка совместимости
компонентов — `data/conditional-extending.json`.

В `tasks/<id>/condition-check.json` сохраняются:

- результат проверки исходной задачи и контрпримеры без условия;
- общее и проверенное число ослаблений;
- объект, построение, номер и описание каждого исследованного варианта;
- размерность, число проб, свободные координаты и невязки;
- число поддерживающих обобщение картинок, действительно отличающихся от исходного определения.

`rejected` означает найденное численное обобщение. `accepted` — найденные
контрпримеры для всех альтернатив каталога. `inconclusive` попадает в раздел
`review`; `timeout` — в раздел таймаутов. Полное условие доступно и для
отбракованных задач. Схема JSON различает проверку истинности и покрытие
ослаблений: старый положительный ответ только о восьми картинках не принимается
за прохождение нового Extending.

Это численная проверка, не формальное доказательство и не поиск всех возможных
обобщений. Поддерживается прежний условный режим Triangle и его ограниченная
область подбора. Не гарантирован охват всех компонент множества решений.

Результаты испытаний: [CONDITIONAL_EXTENDING_REPORT.md](CONDITIONAL_EXTENDING_REPORT.md).


## Стартовые конфигурации

Условный Extending использует ту же параметризацию старта, что генератор и
независимая проверка. Параметры ослабленного объекта добавляются после параметров
формы; размерность больше не зашита как 2. После замены пересчитываются потомки.

Дополнительно проверяется необходимость самого начального ограничения:
RightTriangle → Triangle и CyclicQuadrilateral → Quadrilateral. Такие проверки
попадают в отчёт как `initial-layout` и входят в totalVariants. Нерешённая
проверка начального ограничения препятствует accepted наравне с определениями.
Для прочих стартов нет дополнительного ограничения этого вида.

Все семь имён стартов читаются из .geo и Python-оболочкой, и прямой C#-командой.
Обычный Haskell Extending также получил LineAndPoint и LineAndTwoPoints.
Geometry получает witness переменной длины согласно старту, включая явный
объект прямой для стартов с прямой.
