# Расширение набора утверждений: предложение

Отношения длин и направленные углы реализованы в feature/family-discovery:
см. METRIC_THEOREMS.md и METRIC_THEOREMS_REPORT.md. Произведения отрезков
пока не реализованы. Ниже сохранён план дальнейшего развития. Код просмотрен: сейчас используются
коллинеарность, вписанность, конкурентность, параллельность, перпендикулярность,
касания, равенства отрезков и принадлежность. EqualObjects существует как
внутренний тип; совпавшие объекты обычно исключаются при построении.

## 1. Фиксированные отношения длин

Начать с AB = 2 CD, AB = 3 CD, AB² = 2 CD² и небольшого явно заданного
набора коэффициентов. Это ограниченное семейство, а не подбор произвольного
коэффициента по одной численной картинке.

В Finders добавить SquaredLengthRatioTheoremFinder. Для каждого отрезка
кэшировать квадрат длины на каждой численной картинке. Сопоставлять значения
и заданные коэффициенты через индекс; финально перепроверять кандидатов на
всех картинках с согласованной относительной погрешностью. При добавлении
точки вводятся только отрезки с новой точкой. Нулевые отрезки исключаются.
Без индекса перебор пар отрезков уже стоит O(n^4).

Первоначальное построение таблицы квадратов длин стоит O(p*n²), где p —
число численных картинок. Получение новых отрезков — O(p*n). Дальнейшая цена
зависит от размера фиксированного набора коэффициентов и числа совпадений;
сам индекс не ограничивает возможный объём выдачи. Равенство длин с
коэффициентом 1 оставляем существующему типу без дублирования.

## 2. Равенства направленных углов

Искать angle(l1,l2) = angle(l3,l4) modulo pi, включая линии по парам точек.
Это существенно расширяет выразительность: биссектрисы, изогональность,
спиральные подобия. Но даёт много записей тех же параллельностей,
перпендикулярностей и вписанностей.

Новый EqualDirectedAnglesTheoremFinder должен хранить уникальные направления
геометрических прямых, а не все одинаковые именования одной прямой. Для
пары направлений использовать численную сигнатуру (cos(2a),sin(2a)), чтобы
не создавать разрыв при переходе через pi. Индексировать сигнатуры;
сопоставленные варианты проверять на остальных картинках. При новом объекте
обновлять только пары, содержащие новые направления. Проверки вырожденных
линий обязательны. Соседние численные ячейки тоже проверяются, чтобы
квантование не теряло совпадения на границе.

Если прямых M=O(n²), пар направлений O(M²)=O(n^4). Попарное сравнение всех
углов дало бы O(n^8); его не вводим. Индекс убирает это сравнение, но не
стоимость самих O(n^4) сигнатур и не огромные группы совпадений. Начинать
следует с явно ограниченного набора прямых: именованных и участвующих в
построениях; включение всех соединяющих прямых — отдельная настройка.
Эквивалентные записи одного равенства канонизировать, простые следствия уже
найденных отношений направлений убирать отдельной дешёвой проверкой.

## 3. Равенства произведений отрезков

AB*CD = EF*GH: пропорциональность, степени точек, метрические следствия.
Считать квадраты произведений через таблицу квадратов длин, без корней.
Начать с структурных шаблонов, например PA*PB = PC*PD, и ограниченного
набора отрезков. Произвольные четыре отрезка дают слишком большой перебор.
Сопоставлять произведения по индексу, подтверждать на всех картинках.
Не выводить все перестановки одной формулы и случаи, сводящиеся к уже
известным равенствам отдельных множителей. Цикличность и степень точки
потребуют проверки повторяющегося содержания, а не только текста записи.

## Что нужно изменить помимо finder

Для каждого действительно нового типа нужны TheoremType и каноническое
представление в Core, проверка в Constructor/TheoremVerifier, подключение
в IoC и SoughtTheoremTypes, форматирование/парсинг, совместимость с прувером,
поток GeoGen, JVM-конвертер и отображение Geometry, разбор и численная проверка
в Extending и обработка standard_reasoning/quality. Неподдерживаемый тип
не должен молча приниматься downstream. Если прувер пока не имеет правил
нового типа, статус «не доказано» не означает нетривиальность.

До завершения всей цепочки новый finder можно испытывать отдельно в C#:
вызовы/время, кандидаты, численные совпадения, вырожденные примеры и повторы.
Данные этого режима не выдаются пользователю как проверенные задачи.

## Влияние на ранги и измерения

Новые типы включать явно, по одному. Сохранять счётчики и время отдельно по
типам. На первых испытаниях не добавлять их автоматически в старую метрику:
добавление сотен эквивалентных угловых записей иначе резко изменит ранги
без реального изменения геометрии. Нужны отдельные переключатели «искать
для выдачи» и «учитывать при отборе», с весами по типам.

Сравнение: одинаковые сюжеты и бюджеты, старая выдача сохранена, фиксируются
время finder, факты после прувера, готовые задачи, таймауты и классы повторов.
Правильность проверяется положительными/ложными/вырожденными примерами и
независимыми картинками. Новизна и сложность численным совпадением не доказываются.

Приоритет: сначала ограниченные отношения длин и проверка индекса отрезков;
затем углы на ограниченном наборе прямых; затем структурные произведения.
