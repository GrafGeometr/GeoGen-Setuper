# Отношения длин и равенства направленных углов

Версия ветки feature/family-discovery. Включает также отдельный просмотр
отбраковок и таймаутов из RESULT_BROWSER.md.

## Сборка

Если сборщик уже установлен:

```bash
cd /путь/к/GeoGen-Setuper
git fetch origin
git switch feature/family-discovery
git pull --ff-only origin feature/family-discovery
bash build.sh build --output ./dist/geometry-suite-metric --jobs 2 --test
```

Для нового каталога исходников:

```bash
git clone --branch feature/family-discovery --single-branch \
  https://github.com/GrafGeometr/GeoGen-Setuper.git
cd GeoGen-Setuper
bash build.sh deps
bash build.sh build --output ./dist/geometry-suite-metric --jobs 2 --test
```

При уже установленном сборщике передайте его кэш через
--state /абсолютный/путь/к/GeoGen-Setuper/.builder. Для первой установки
Debian/Ubuntu сначала bash build.sh deps. Результат сборки должен иметь новое
имя каталога. Сборщик накладывает 19 патчей на закреплённые исходники GeoGen,
Extending и Geometry; отдельно править исходные репозитории не нужно.

## Включение

По умолчанию набор искомых утверждений прежний. Новые типы включаются явно:

```bash
./dist/geometry-suite-metric/geometry-suite run ./stories/hard.txt \
  --extra-theorems LengthRatio2 LengthRatio3 SquaredLengthRatio2 EqualAngles \
  --search-config ./4.json --output ./runs/hard-metric-001 \
  --timeout 660 --workers 1 --check-ms 5000 \
  --standard-checks --quality-checks --view
```

Можно выбрать любой поднабор, например --extra-theorems EqualAngles.
--search-config необязателен: новые утверждения ищутся и при обычном обходе.
Число итераций и ограничения объектов остаются в story-файле. Указывайте новый
output. Без графической сессии уберите --view.

Для семейной кампании тот же параметр доступен у discover:

```bash
./dist/geometry-suite-metric/geometry-suite discover ./my-family/family.json \
  --extra-theorems LengthRatio2 EqualAngles \
  --output ./runs/family-metric-001 --budget 10m \
  --search-workers 1 --check-workers 1 --check-ms 5000 --view
```

Вместо family.json укажите свой файл семейства. Кампания сохраняет выбранные
типы и восстанавливает их при resume. Одиночный resume продолжает обработку
очереди, а не генерацию. Для прямого запуска C# можно добавить имена типов
в TheoremFindingSettings.SoughtTheoremTypes. В комплекте оболочка дополнительно
подключает соответствующие файлы правил *.metric как *.txt в каталоге запуска;
для прямого запуска это нужно сделать отдельно.

## Значение типов

| Тип | Смысл |
|---|---|
| LengthRatio2: A, B, C, D | Один из отрезков AB, CD вдвое длиннее другого |
| LengthRatio3: A, B, C, D | Один из отрезков AB, CD втрое длиннее другого |
| SquaredLengthRatio2: A, B, C, D | Квадрат одной длины вдвое больше квадрата другой, то есть отношение длин sqrt(2):1 |
| EqualAngles: [A, B], [C, D], [E, F], [G, H] | Направленный угол между первыми двумя прямыми равен углу между последними двумя по модулю 180° |

Отрезки в утверждении не упорядочены: AB=2CD и CD=2AB входят в один тип
LengthRatio2. Нулевые отрезки не считаются подходящими. Коэффициенты пока
фиксированы перечисленными тремя типами; произвольного коэффициента из JSON нет.

Углы задаются четырьмя прямыми. Прямая может быть именованной либо заданной
двумя точками. Порядок прямых ВНУТРИ угла существенен. Перестановка двух углов,
одновременная смена их знаков и перегруппировка членов одной и той же линейной
формулы объединяются. Коэффициенты не делятся на общий множитель: это было бы
неверно для углов по модулю 180°.

Поиск исключает углы 0°/90°, соответствующие уже имеющимся параллельности и
перпендикулярности. Также исключается простой перенос между попарно
параллельными направлениями и прямые четырёхточечные записи вписанности,
распознаваемые по концам участвующих прямых. Это ограниченный точный разбор
эквивалентных форм, а не полная проверка тривиальности. Для каждой геометрической
прямой выбирается одно представление; все сочетания коллинеарных именований
не размножаются.

Geometry показывает новые темы и условия, подсвечивает участвующие отрезки
и прямые. Неравные отрезки не получают значков равенства. Для направленных
углов не рисуются потенциально неверные отметки равных обычных углов:
точная формула остаётся в условии. Оригинальный MetaPost DrawingLauncher
также обновлён; его проект собирается, но рендер MetaPost отдельно не испытывался.

## Проверки и прувер

Новые типы поддержаны в Core/парсере/форматировании, геометрическом verifier,
сортировке и сопоставлении объектов правил прувера, потоке, дедупликации семейства,
Extending, независимой проверке истинности, стандартном проверяющем и конвертере.
При включённых типах подключаются правила середины, центроида, прямоугольного
равнобедренного треугольника и вписанных углов. Для составных построений
существующий TrivialTheoremProducer тоже использует расширенный finder.

Проверка стандартности углов использует существующую систему направлений;
для отношений длин работают точные аффинные и метрические сертификаты.
Неполучение сертификата означает unknown. Прохождение численных проб не
является доказательством истинности или сложности задачи.

Маркер data/metric-theorems.json проверяет согласованность DLL ядра/finder,
Extending и JAR конвертера. Подмена только одной программы в старом комплекте
не поддерживается. Выполняйте полную сборку.

## Влияние на ранги

При включении новые факты входят в общий набор теорем и по умолчанию имеют
вес 1. Поэтому ранги могут измениться даже с прежними интервалами. Для поиска
новых утверждений без их вклада в взвешенную ранговую оценку добавьте в JSON:

```json
{
  "policy": "soft",
  "seconds": 600,
  "typeWeights": {
    "LengthRatio2": 0,
    "LengthRatio3": 0,
    "SquaredLengthRatio2": 0,
    "EqualAngles": 0
  },
  "rankIntervals": [{"from": 0.3, "to": 0.7}]
}
```

Это влияет на выбор ветвей, а не на старый итоговый рейтинг красоты GeoGen.
minimumNewTheorems считает сырые новые утверждения, поэтому нулевые веса его
не отключают. Полный [0,1] без других предпочтений не включает ранговый просмотр,
но включённые новые finder всё равно ищут утверждения в обычном обходе.

## Цена поиска

Квадраты длин отрезков индексируются по логарифму величины. Проверяются соседние
ячейки и все численные картинки. Сигнатуры углов индексируются по удвоенному
направленному углу; геометрическая проверка использует cos(2a),sin(2a).
Относительная численная погрешность сравнения — 1e-8, ширина ячейки — 1e-7.

Нет попарного сравнения всех углов со всеми углами. Для n точек и M геометрических
прямых стоимость построения индексов — O(p*n²) для каждого коэффициента и
O(p*M²) для углов, где p — число картинок, плюс обработка совпавших кандидатов
и вывод фактов. При инкрементальном вызове выдаются только новые отношения;
индекс текущей картинки пока перестраивается, а не наследуется от родителя.

Весь поиск — C#. Вызовов Python из цикла генерации нет. Расширение выдачи может
увеличить суммарную стоимость прувера, Extending и обработки очереди даже при
быстром finder. Если все точки на одной окружности, касаний проверяется мало,
а углов может быть много: универсальной гарантии «не дороже касаний» нет.
Замеры и ограничения испытаний — в METRIC_THEOREMS_REPORT.md.
