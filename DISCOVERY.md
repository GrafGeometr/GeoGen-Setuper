# Поиск внутри пользовательского семейства

Реализован первый этап концепции 2: пользователь задаёт исходные сюжеты и разрешённые построения, программа создаёт ограниченный банк дополнений и исследует его несколькими независимыми GeoGen. Картинки разных запусков объединяются в одну ленту Geometry.

## Подготовка семейства

Скопируйте поставляемый пример из **нового собранного комплекта** в удобный каталог:

```bash
cp -r ./dist/geometry-suite-discovery/examples/families/triangle ./my-family
```

В `my-family/stories/` находятся обычные story-файлы GeoGen, в `my-family/family.json` — настройки:

```json
{
  "version": 1,
  "name": "Проекции и середины в треугольнике",
  "stories": ["stories/*.txt"],
  "allowedConstructions": ["Midpoint", "PerpendicularProjectionOnLineFromPoints", "Orthocenter"],
  "includeRelaxations": true,
  "seed": 17,
  "growth": {"maxAddedDefinitions": 1, "variantsPerStory": 6},
  "search": {"maxDepth": 3, "maxJobs": 12, "sliceSeconds": 15, "maxPaletteSize": 2}
}
```

Пути и маски stories разрешаются относительно файла семейства, а не текущего каталога терминала. Сюжетов может быть несколько. В family.json неизвестные параметры считаются ошибкой, чтобы опечатки не меняли режим незаметно.

- `allowedConstructions`: общий разрешённый пул. Если поле отсутствует — объединение списков Constructions исходных story. Все исходные списки должны входить в пул. Эти построения можно применять и для дополнений начального сюжета, и для дальнейшего поиска.
- `includeRelaxations`: дополнительно исследовать ослабленные базы. Сейчас поддержаны RightTriangle → Triangle и CyclicQuadrilateral → Quadrilateral. Исходный сюжет остаётся отдельным исходником; его определения не заменяются. Если ослабленный сюжет уже дан другим файлом, один поиск сохраняет обе записи происхождения.
- `seed`: воспроизводимый выбор символических вариантов и палитр. Случайные численные картинки GeoGen и пробы Extending пока используют свои прежние RNG; побитовое повторение всего запуска не обещается.
- `maxAddedDefinitions`: максимум дополнительных определений поверх пользовательской конфигурации, 0..5. Менять/удалять исходные определения этот режим не умеет и не пытается.
- `variantsPerStory`: ограничение ширины дополнений на каждом уровне для каждой исходной/ослабленной базы. Это не число гарантированно хороших сюжетов.
- `maxDepth`: общий верхний предел числа добавленных определений плюс дальнейших итераций. Iterations исходного story также ограничивает глубину каждого отдельного запуска.
- `maxJobs`: предел числа разных поисковых заданий кампании. Кампания может исчерпать этот банк раньше времени.
- `sliceSeconds`: максимальное время одного GeoGen. Полученные до остановки события сохраняются. Незавершённый DFS с точного места пока не восстанавливается.
- `maxPaletteSize`: размер автоматически выбранного подмножества. Исходный список Constructions также исследуется; ограничение относится к дополнительной палитре.

HiddenPoints сохраняются и исключаются из аргументов новых дополнений. Лимиты точек/прямых/окружностей учитывают и дополнения, и дальнейший поиск: перенос построения в начальный сюжет не обходит лимит.

Подбор аргументов проверяет типы и симметрии сигнатур. Очевидные тождества, включая аффинные совпадения и ортоцентр прямоугольного треугольника, не добавляются повторно. Окончательную геометрическую допустимость проверяет GeoGen. Недопустимый автоматически добавленный вариант имеет состояние `invalid`, исходный ошибочный сюжет — `failed`; причины остаются в журнале задания.

## Запуск и продолжение

```bash
./dist/geometry-suite-discovery/geometry-suite discover ./my-family/family.json \
  --output ./runs/my-family-001 --budget 10m \
  --search-workers 2 --check-workers 2 --check-ms 1000 --view
```

Каталог output должен быть новым. `--budget` задаёт общее активное время поиска, а не время каждого процесса: 30s, 10m, 8h. Задания исследуются независимо, число производителей и проверок ограничивается отдельно. После поиска предусмотрено до 30 секунд на запуск оставшихся проверок; уже работающие проверки имеют свой лимит и время конвертации. Необработанное остаётся в очереди.

```bash
# Продолжить оставшиеся задания/проверки; готовое не пересчитывается:
./dist/geometry-suite-discovery/geometry-suite resume ./runs/my-family-001

# Добавить время поиска, если первоначальный бюджет исчерпан:
./dist/geometry-suite-discovery/geometry-suite resume ./runs/my-family-001 --budget 10m

# Повторить ошибки и таймауты:
./dist/geometry-suite-discovery/geometry-suite resume ./runs/my-family-001 --retry-errors

# Открыть общий список независимо от поиска:
./dist/geometry-suite-discovery/geometry-suite watch ./runs/my-family-001

# Получить каталог всех построений, сигнатур и сквозной поддержки баз:
./dist/geometry-suite-discovery/geometry-suite catalog
```

`resume` не повторяет завершённые задания. После прерывания незавершённый внутренний DFS не запускается заново автоматически; его находки сохраняются, а кампания переходит к ещё не запущенным вариантам. Исчерпанный банк maxJobs не расширяется командой resume: для большего банка создайте новую кампанию с изменённым family.json.

Кампания содержит собственные копии сюжетов и настроек, поэтому исходные файлы после её создания для продолжения не нужны. `family/config.json` внутри кампании можно использовать для нового запуска. Изменение сборки или модулей проверок блокирует использование старого кэша кампании. При неизменном каталоге построений `resume --recheck` обновляет проверяющую сборку и пересчитывает кандидатов с архивированием прежних картинок и базы; при изменении каталога нужна новая кампания. Между независимыми кампаниями кэш пока автоматически не объединяется. Подробнее: [QUALITY.md](QUALITY.md).

## Отбор и происхождение

В общей SQLite-базе сохраняются задания, кандидаты и все источники совпадающих находок. Повторы объединяются до Extending: допустимое переименование базовых объектов, перестановка независимых определений, симметрии аргументов, явная/неявная запись прямой в заключении. Условия остаются частью ключа. Неизвестная запись сравнивается только по точному тексту.

Это структурное объединение, не полный решатель геометрической эквивалентности разных макросов. Первая найденная запись остаётся представителем. Отдельный постоянный межкампанийный геометрический индекс — следующий этап.

При выборе оставшихся заданий учитывается сумма оценок компактности уникальных ready-задач, прошедших проверку истинности, на время по источнику, палитре, ослаблению и виду дополнения. Каждое четвёртое назначение сохраняет обычный порядок исследования. Такая простая стратегия ещё не измеряет красоту задач и не управляет произвольными ветками внутри DFS.

Основные файлы:

- `results.tsv`, `stream-status.txt`: общая лента, которую читает Geometry;
- `geo/`: готовые проверенные картинки с типом и оценкой в имени;
- `tasks/ID/worker.log`: диагностика Extending/конвертера;
- `tasks/ID/standard-proof.json`: объяснение стандартного доказательства;
- `tasks/ID/quality.json`: структура, пробная проверка истинности и диагностические признаки;
- `tasks/ID/quality-worker.log`: исходный ответ независимого проверяющего;
- `searches/JOB/origin.json`: исходник, дополнение, ослабление и палитра;
- `searches/JOB/inputs/input_story.txt`: фактически запущенный сюжет;
- `searches/JOB/geogen.log`: журнал конкретного GeoGen;
- `family/`: снимок исходных файлов и каталога возможностей;
- `tasks.sqlite`: задания, кандидаты, связи origins и ключи повторов.

## Первые стандартные фильтры

В кампании включены точные, неполные угловой, аффинный и метрический модули, проверенные шаблоны известных утверждений, а также независимые пробы истинности. В прежнем ручном режиме они включаются явно:

```bash
./dist/geometry-suite-discovery/geometry-suite run ./stories/example.txt \
  --output ./runs/example-standard --standard-checks --quality-checks --view
```

Угловой модуль работает с целыми комбинациями направлений по модулю 180°, не делит сравнения на произвольные коэффициенты. Поддержаны связи параллельных/перпендикулярных прямых, биссектрис, часть проекций, вписанности исходного четырёхугольника и принадлежностей некоторым построенным окружностям. Необходимые прямые должны быть определены; неизвестные построения не превращаются в свободные аксиомы.

Аффинный модуль поддерживает середины, центроиды, отражение относительно точки и их точные рациональные комбинации. Он может доказывать часть коллинеарностей, равенств отрезков, параллельностей и конечной конкурентности. Метрический модуль использует точные рациональные комбинации скалярных произведений: поддержаны часть свойств проекций, ортоцентра, центра окружности, диаметров, середин дуг и равных касательных. Для точки Понселе распознаются два проверенных шаблона, включая радиус к середине хорды и случай окружности с заданным диаметром. Все численно найденные факты и сама цель исключены из посылок: используются только поддержанные определения и исходные условия.

Найденный короткий вывод (до 12 использованных источников, консервативная первая оценка) получает статус `standard`, сертификат сохраняется, Extending и конвертация не запускаются. Это не оценка общей трудности доказательства. Нераспознанное продолжает обычный конвейер. После Extending задача проверяется на 8 независимых точных картинках; контрпример или незавершённая проверка дают `review`, успешные пробы — `ready` с явным указанием границ проверки. Равенства отношений, Чева/Менелай, степень точки и поиск согласованных обобщений ещё предстоят.

Фильтры первой версии реализованы на Python с точной стандартной арифметикой, чтобы поставить общий контракт вместе с кампанией без нового runtime. Перенос горячих участков в C# решается по измерениям. Кэши контекстов ограничены; сертификат привязан к условиям и заключению и перепроверяется до отбраковки.

Если Extending отвечает ровно `Ratio has zero denominator`, делается ограниченная повторная случайная проба в пределах прежнего check-ms. Ошибки не считаются успешной проверкой; остальные ошибки не повторяются автоматически. Все ответы сохраняются в worker.log.

## Границы первого выпуска

Реализованы пользовательские семейства, добавление типизированных определений, два ослабления баз, конечный банк заданий, параллельный диспетчер, структурное объединение, происхождение, сохранение, простая адаптация и первые стандартные фильтры.

Следующие этапы: более сильное геометрическое объединение и общий архив разных кампаний; расширение операторов изменения сюжетов; полноценные сертификаты для существующего прувера; отношения и согласованные обобщения; раннее стандартное замыкание внутри finder; управляемый сохраняемый фронтир GeoGen. Контроль памяти/диска на уровне ОС не добавлен; для начала используйте небольшое число процессов и ограниченный банк.
