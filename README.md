# GeoGen-Setuper — Linux-сборщик Geometry Suite

Без Git можно скачать **Code → Download ZIP** на странице репозитория,
распаковать архив и открыть терминал в получившейся папке. В этом случае
начинайте с команды `bash build.sh deps`.

Консольная программа на Python (только стандартная библиотека) и короткий Bash entrypoint.
Собирает GeoGen, GeometryExtending, Geometry Desktop и исходный GeoGenIntegration
в один каталог с собственными .NET runtime и Java runtime. Конвертер собирается
из того же Kotlin-кода под JVM, поэтому Windows/Kotlin Native не требуется.

## Быстрый старт

Поддерживаемая цель: Linux x86_64, Debian 12/13 либо Ubuntu 22.04/24.04,
Python >= 3.10, JDK 17. Для первой сборки нужны Интернет и примерно 12 ГБ
свободного места с запасом. При установке GHC временный раздел должен вмещать
порядка 7 ГБ: распаковка и промежуточная установка занимают существенно больше
места, чем скачиваемый архив. После установки временные файлы удаляются.
Первый запуск скачивает SDK и библиотеки и может занять десятки минут.

```bash
git clone https://github.com/GrafGeometr/GeoGen-Setuper.git
cd GeoGen-Setuper
bash build.sh deps       # Debian/Ubuntu: системные пакеты через apt/sudo
bash build.sh doctor
bash build.sh build
```

`deps` — единственная команда, использующая apt/sudo. Она явно устанавливает
перечисленные в builder.py системные зависимости. `build` не использует sudo:
локально устанавливает недостающие .NET SDK 7.0.410, GHC 9.6.6, Cabal и Gradle 7.2.
JDK 17 и C toolchain должны быть установлены до сборки (командой deps или вручную).
По умолчанию исходники клонируются из трёх репозиториев GrafGeometr на коммиты,
записанные в sources.json. Скрипты установки .NET/GHCup скачиваются с официальных
сайтов; Gradle проверяется по опубликованному SHA-256.

Готовый комплект: `dist/geometry-suite/`. Кэш, инструменты и логи: `.builder/`.
Сборка обязательным образом выполняет проверку GeoGen → конвертер → .geo,
а также два контрольных примера Extending. Ошибка останавливает сборку.
Существующий каталог результата не перезаписывается: задайте другой --output.
Не удаляйте .builder, если хотите повторно использовать скачанные зависимости.

## Существующие исходники и инструменты

Если рядом лежат GeoGen/, Geometry/, GeometryExtending/:

```bash
bash build.sh build --sources /path/to/projects --output /path/to/new-suite
```

Репозитории копируются в рабочий каталог; оригинальные исходники не меняются.
Локальные изменения включаются в копию, их наличие отмечается в BUILD.json.

```bash
bash build.sh build --sources /path/to/projects \
  --dotnet /path/to/dotnet --gradle /path/to/gradle-7.2/bin/gradle \
  --state /path/to/build-cache --output /path/to/new-suite --jobs 2 --test
```

Поддерживаются JAVA_HOME, PATH (ghc/cabal), CABAL_DIR, NUGET_PACKAGES,
GRADLE_USER_HOME, HTTP_PROXY/HTTPS_PROXY/NO_PROXY. Для дополнительной настройки
Gradle предусмотрен GEOMETRY_GRADLE_ARGS, например `--offline` или свойства JVM.
Значения секретов в аргументы передавать не следует: команды сохраняются в логах.
`--offline` предназначен для существующих исходников, уже установленных инструментов
и заполненных кэшей. Подключения к Git в режиме --sources не требуются.
`--test` дополнительно запускает существующие тесты GeoGen.

## Запуск готового комплекта

```bash
./dist/geometry-suite/geometry-suite doctor
./dist/geometry-suite/geometry-suite run ./my-input.txt --output ./run-001
./dist/geometry-suite/geometry-suite watch ./run-001
```

`run` получает сюжет в существующем текстовом формате GeoGen (см. examples/).
По умолчанию работает поток: GeoGen публикует интересные находки по мере поиска,
Extending сразу проверяет их, прошедшие фильтр задачи конвертируются в `.geo`.
Каталог запуска должен быть новым. Финальные подборки лучших теорем GeoGen
сохраняются отдельно в `geogen/`; поток включает находки до глобального отбора.

```bash
# Поток с окном результатов; новые задачи не переключают выбранный чертёж.
./dist/geometry-suite/geometry-suite run ./my-input.txt --output ./live-001 --view
# Программное рисование для виртуальной машины:
./dist/geometry-suite/geometry-suite watch ./live-001 --software
# После Ctrl+C: обработать оставшуюся очередь, не повторяя готовые задачи.
./dist/geometry-suite/geometry-suite resume ./live-001
# Явно повторить ошибочные проверки/конвертации и таймауты:
./dist/geometry-suite/geometry-suite resume ./live-001 --retry-errors
# Прежний пакетный режим:
./dist/geometry-suite/geometry-suite run ./my-input.txt --output ./batch-001 --batch
```

`--workers 2` ограничивает число параллельных обработчиков находок (1..64).
`--check-ms 1000` задаёт лимит одной проверки Extending; внешний процесс также
ограничен по времени. `--timeout 3600` ограничивает время поиска GeoGen:
при его превышении полученные находки сохраняются и очередь обрабатывается,
а запуск получает статус сбоя. Это не лимит общей длительности всей очереди.
`--no-check` пропускает Extending и явно помечает результат «Без проверки».

В Geometry слева показан обновляемый список и состояние поиска. По умолчанию
видны готовые задачи; снимите «Только готовые», чтобы увидеть очередь, отбраковки,
таймауты, ошибки и точные повторы. Выбранный чертёж сохраняется при новых поступлениях.
Статус «Готово» означает прохождение фильтра Extending и успешную конвертацию,
а не формальное доказательство теоремы.

Каждая находка публикуется завершённым JSON-файлом в `events/` через переименование.
Состояния хранятся в `tasks.sqlite`; `results.tsv`, `stream-status.txt` и
`run-state.json` автоматически обновляются для просмотра. Подробности конкретной
ошибки остаются в `tasks/ID/worker.log`; работа GeoGen — в `geogen.log`.
Повторы одинаковых строк конфигурации/утверждения не проверяются повторно;
геометрически эквивалентные находки могут оставаться в потоке.

Ctrl+C останавливает GeoGen, сохраняет очередь и результаты активных проверок.
`resume` продолжает **обработку уже полученных находок**, без восстановления дерева
поиска GeoGen. Одновременно обрабатывать один каталог двумя процессами запрещено
блокировкой. Разные каталоги запусков независимы. Не редактируйте файлы событий и
базу вручную, особенно во время работы. Для больших поисков учитывайте, что
все события и диагностические файлы сохраняются и занимают место.

```bash
geometry-suite convert ./ReadableBestTheorems/CollinearPoints.txt ./new-geo
geometry-suite check ./new-geo
geometry-suite view ./example.geo --software
geometry-suite smoke --output ./new-smoke-dir
```

`convert` принимает только формат ReadableBestTheorems, не ReadableWithoutProofs.
`check` — отдельная старая пакетная команда, сохраняющая исходное поведение Extending: BAD_ снимается перед повторной
проверкой и добавляется при отбраковке. Поэтому проверяйте копии важных файлов.
Лог пишется в extending.log, сводка — в extending-report.json. Этот старый режим Extending
не возвращает надёжного статуса каждой задачи: parse error/таймаут не равнозначны
успешной проверке, а not_rejected в сводке означает только отсутствие BAD_.

## Скрытые исходные точки

После определений исходной конфигурации, перед `Iterations:`, можно добавить:

```text
HiddenPoints: A, B, C
```

Эти точки сохраняются в исходной конфигурации, выводе, чертеже и поиске теорем,
но не могут быть непосредственными аргументами **новых** построений. Другие
исходные объекты, уже определённые через них, остаются доступны для перебора.
Можно скрывать как свободные, так и построенные исходные точки. Неизвестные имена,
повторения и имена прямых/окружностей считаются ошибкой. Без `HiddenPoints:`
работает прежний формат. Скрытие не меняет математический смысл режима симметрии.

Полный пример: `dist/geometry-suite/examples/input_hidden_points.txt`.

```bash
./dist/geometry-suite/geometry-suite run \
  ./dist/geometry-suite/examples/input_hidden_points.txt --output ./hidden-run-001
```

В нём A/B/C скрыты, D/E построены через них и доступны для перебора:
генератор добавляет только Midpoint(D, E). На этом маленьком примере подборка
интересных теорем может оказаться пустой — смотрите число конфигураций в geogen.log.

Функция поставляется патчем `patches/hidden-points.patch` к закреплённой версии
GeoGen. Сборщик проверяет и применяет его только в рабочей копии.
Передаваемые через `--sources` исходники GeoGen должны быть без этого патча;
если вы уже применили его вручную, используйте стандартную загрузку исходников.

## Что исправляется в рабочих копиях

- Geometry Desktop: живой список результатов, встроенный DejaVu Sans; подключаются общие исходники из Android-каталога;
  данные размещаются по XDG_DATA_HOME/~/.local/share, исправляется второй CLI-аргумент.
- GeoGenIntegration: тот же Main.kt собирается под JVM вместо mingwX64.
- GeometryExtending: структурированный режим --check-file, строгое вычисление внутри таймаута; добавляются -threaded -rtsopts; число ядер автоматически не навязывается.
- GeoGen: поддержка HiddenPoints (включая фильтры эквивалентности), атомарный поток находок; global.json фиксирует SDK 7.0.410; правила и примеры входят в комплект.
- Настройки GeoGen формируются заново для каждого запуска с актуальными путями.

## Ограничения

Комплект можно перемещать, включая каталоги с пробелами. Для запуска нужны Python
3.10+, системные библиотеки glibc/GMP/FFI/NUMA/ICU/OpenSSL и графические библиотеки.
Java и .NET устанавливать отдельно не нужно. На старой glibc бинарник, собранный
на новом дистрибутиве, может не запуститься: для распространения собирайте на
самой старой поддерживаемой ОС. Это не универсальный статический AppImage.
GUI требует рабочего стола; --software помогает в виртуальных машинах.
.NET 7 оставлен для совместимости исходного проекта; переход на поддерживаемую
версию .NET — отдельная последующая работа.

Закреплены исходные коммиты и основные инструменты. Транзитивные зависимости
Gradle/NuGet ещё не снабжены полным lockfile; Cabal freeze и фактические версии
исходников сохраняются в комплекте. Побитовая воспроизводимость не заявляется.
Наборы конструкций/теорем в трёх программах не полностью совпадают: неподдерживаемый
конвертером объект получает статус ошибки в потоке (другие находки продолжают обрабатываться).
В старом пакетном режиме такая ошибка останавливает стадию конвертации.

Проверка самого сборщика: `python3 -m unittest discover -s tests -v`.
