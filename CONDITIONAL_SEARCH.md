# Поиск задач с одним дополнительным условием

Это отдельный, явно включаемый режим. Без `--conditions-config` работает прежний
генератор. Условие не участвует в построении дерева конфигураций и его ранговом
отборе: оно вводится только в готовой конфигурации на последней разрешённой
итерации, перед повторным поиском итоговых теорем.

## Получение локальной версии

Полная версия опубликована в ветке `feature/family-discovery`:

```bash
git clone --branch feature/family-discovery --single-branch https://github.com/GrafGeometr/GeoGen-Setuper.git
cd GeoGen-Setuper
```

Для существующего клона выполните `git fetch origin`,
`git switch feature/family-discovery` и
`git pull --ff-only origin feature/family-discovery`.

## Сборка и запуск

Соберите именно исходники, содержащие `patches/conditional-search-geogen.patch`:

```bash
bash build.sh build --output ./dist/geometry-suite-conditions --jobs 2 --test
```

Для первого теста используйте пример из собранного комплекта:

```bash
./dist/geometry-suite-conditions/geometry-suite run \
  ./dist/geometry-suite-conditions/examples/conditions/triangle-centres.txt \
  --conditions-config ./dist/geometry-suite-conditions/examples/conditions/automatic.json \
  --output ./runs/conditions-001 --workers 2 --check-ms 5000 \
  --timeout 660 --standard-checks --quality-checks --view
```

`--view` требует графической сессии; на сервере уберите этот флаг.
Путь `--output` должен быть новым. После окончания поиска очередь продолжает
проверять уже найденные задачи. `--timeout` ограничивает процесс поиска, а не
время обработки всей очереди. Ctrl+C сохраняет очередь; обработку продолжает:

```bash
./dist/geometry-suite-conditions/geometry-suite resume ./runs/conditions-001 --workers 2
```

`--search-config ./4.json` можно добавить независимо: ранговые интервалы
применяются к обычному дереву построений, условный поиск — к его конечным
конфигурациям. `--extra-theorems LengthRatio2 LengthRatio3 SquaredLengthRatio2
EqualAngles` расширяет заключения; эти четыре типа пока не перебираются как
условия. Пакетный `--batch` и экспериментальный Python-сэмплер несовместимы
с условным режимом.

Для семейства:

```bash
./dist/geometry-suite-conditions/geometry-suite discover ./my-family/family.json \
  --conditions-config ./conditions.json --output ./runs/family-conditions-001 \
  --budget 10m --search-workers 1 --check-workers 2 --check-ms 5000
```

Все исходные сюжеты должны иметь layout `Triangle`. Настройки условий
копируются в каталог кампании и восстанавливаются при `resume`. Короткий
`sliceSeconds` семейства может оборвать подбор условий раньше общего
`seconds`: для начального эксперимента разумно дать одному заданию 60–120 с.

## Минимальный JSON

```json
{
  "version": 1,
  "seconds": 600,
  "types": ["CollinearPoints", "ConcyclicPoints", "ParallelLines",
            "PerpendicularLines", "EqualLineSegments"]
}
```

За раз добавляется ровно одно условие. Типы чередуются; внутри используются
воспроизводимые перестановки кандидатов. Условий несколько одновременно нет.
`conditions` можно не задавать: программа сама перечислит варианты.

Для проверки конкретного условия:

```json
{
  "version": 1,
  "seconds": 60,
  "types": ["EqualLineSegments"],
  "conditions": ["EqualLineSegments: A, B, A, C"]
}
```

Имена здесь соответствуют каноническому выводу GeoGen: A, B, C — исходные
вершины; следующие точки получают D, E и т. д. Это не сохранение произвольных
имён из входного story. Условие должно ссылаться на существующие объекты
каждой исследуемой конфигурации. Базовый пример с равнобедренным треугольником
может ничего не показать: известные следствия отсекает прувер.

Продвинутые настройки (не обязательны):

| Поле | По умолчанию | Что ограничивает |
|---|---:|---|
| `seconds` | 600 | Время обычного обхода + подбора условий + анализа в данном поисковом задании; начальная инициализация отдельно |
| `seed` | 61 | Порядок условий и начальные приближения |
| `samples` | 8 | Число различных регулярных картинок с выполненным условием; 4…32 при генерации, независимая проверка всегда требует 8 |
| `starts` | 80 | Максимум независимых начальных приближений на одно условие, не меньше `samples` |
| `iterations` | 60 | Максимум шагов численного решателя на одно начальное приближение; это **не** число построений |
| `minSampleDistance` | 0.04 | Минимальное расстояние между формами треугольника в координатах C при A=(0,0), B=(1,0) |
| `maxConditionsPerConfiguration` | Без практически достижимого лимита | Дополнительный предел числа условий в одной конечной конфигурации |
| `requireLastObject` | true | Последний построенный объект должен явно участвовать в условии либо заключении |

Число построений задаётся прежним `Iterations:` в story-файле. Последний этап
определяется этим числом и бюджетами `MaximalPoints/Lines/Circles`. Если обход
не добрался до разрешённой конечной глубины, для такого префикса условный
поиск не выполняется. Требуется хотя бы одна итерация построений.

## Проверки и файлы

Для каждого кандидата генератор требует, чтобы заключение выполнялось на всех
подобранных картинках и имело минимум два численных контрпримера без условия.
Заключение, совпадающее с условием или известное на обычной конфигурации,
не публикуется. Прувер получает условие как дополнительную посылку.

Очередь заново подбирает 8 картинок с другим seed и ищет минимум два
контрпримера без условия. Она не доверяет переданным генератором координатам.
Если картинок недостаточно — `review`; превышен `--check-ms` — `timeout`;
найден контрпример при выполненном условии — `review`. Это численно проверенная
гипотеза, не математическое доказательство.

Условные задачи теперь проходят Extending с сохранением дополнительной
посылки: каждое построение по очереди ослабляется, затем спуск заново подбирает
картинки для той же посылки. Используется полный каталог: 136 альтернатив для
72 построений. Нерешённые ослабления не считаются успешной проверкой.
`--standard-checks` дополнительно отсекает поддерживаемые короткие точные
следствия, `--quality-checks` сохраняет отчёт проверки. Подробности, значения
статусов и формат отчёта: [CONDITIONAL_EXTENDING.md](CONDITIONAL_EXTENDING.md).

В каталоге запуска:

- `conditions-config.json`, `conditions-settings.json` — входные и разобранные настройки;
- `conditions-trace.jsonl` — число условий, успешных подборов, пересчётов картинки и найденных фактов;
- `events/*.json` — отдельные поля `condition`, `theorem`, `conditionSamples`;
- `tasks/<id>/condition-check.json` — независимые картинки и контрпримеры;
- `conditions/*.txt` — полное копируемое условие задачи;
- `geo/*.geo` — синий цвет дополнительного условия, красный цвет заключения.

Geometry открывает найденное положение вершин. При ручном перемещении вершины
условие может перестать выполняться: ограничений на перетаскивание нет.
`audit --diagrams` дополнительно проверяет выполнение посылки в арифметике
самого Geometry. Команда `check` распознаёт условные `.geo` и направляет их
в новый проверяющий модуль. Старый отдельный MetaPost Drawer условные JSON
отклоняет с явным сообщением; используйте конвертер Geometry Suite.

Ограничения первой версии: только Triangle; A=(0,0), B=(1,0), C=(x,y),
−2≤x≤3, 0.06≤y≤3; исключаются совпадающие объекты и нестабильные построения.
Область ограничивает подбор, но не добавляется молча в текст задачи: выполнение
заключения за её пределами и на всех компонентах множества решений пока
не установлено. Нужны последующая математическая проверка и оценка качества.
