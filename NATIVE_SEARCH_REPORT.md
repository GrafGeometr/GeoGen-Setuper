# Результаты C#-прототипа поиска по числу теорем

18 ноября 2026. Установка, использование и настройка:
[THEOREM_SEARCH.md](THEOREM_SEARCH.md).

**Что сделано.** Из каждого состояния случайно выбирается до B новых
определений. Каждый кандидат действительно строится штатным C#-конструктором.
TheoremFinder находит теоремы полученной конфигурации. По их числу,
числу точек и числу теорем с новой точкой выбираются продолжения.
Это заменяет прежнюю оценку одних аргументов построения.

Координаты родителя переиспользуются, вычисляется добавленный объект.
Используется штатный поиск новых теорем с сохранением действительных старых.
В TheoremFinder убрана лишняя генерация копий старого утверждения, когда
ни один объект в нём не получил нового определения. Расчёт метрики использует
битовые маски участия точек; текущий предел — 63 явно названные точки.
В цикле поиска нет вызова Python и межпроцессного обмена координатами.

**Формула.** По умолчанию D=T/N: T — число различных найденных утверждений,
N — число явно названных точек. В JSON меняются веса типов, степень N,
вес локальных утверждений и область подсчёта: вся картинка, последние точки,
новая точка или точки с наименьшим числом теорем.

На глубине d стоимость кандидата:

```text
target = TargetDensity либо D0 × TargetRatio[d]
cost = DensityWeight[d] × |ln((D+0.5)/(target+0.5))|
     + NewPointWeight[d] × |NewPointDegree−NewPointTarget[d]| / NewPointScale[d]
```

Меньшая стоимость предпочтительнее. В испытанном профиле из 16 кандидатов
сохранялись 4: три лучших и один случайный из оставшихся. Лучшее продолжение
исследуется первым; другие остаются в стеке. После обхода выбранного дерева
предлагаются новые продолжения исходного сюжета. Полного перебора сочетаний нет.
Числа 16 и 4 — стартовые настройки, не установленный оптимум.

**Полноценное сравнение на десяти минутах.** Оба процесса завершились;
связь со средой была потеряна во время их работы, но итоговые файлы сохранились.

Исходный сюжет: Triangle A,B,C; I — инцентр, O — центр описанной окружности,
H — ортоцентр, M — середина BC. Итого 7 точек. Разрешены 11 стандартных
операций, включая середину, центры, отражения, проекцию, пересечения,
точки Шалтая/Болтая. Добавляется до 4 точек за 4 итерации. Seed=17;
4 воспроизводимых численных картинки, допускающих тупоугольные треугольники.

Оба режима использовали B=16, K=4, одну случайную ветвь и один набор формул.
В контрольном режиме выключено только ранжирование. Цели плотности по
глубинам: 1.2,1.1,0.85,0.7 от исходного D0=2. На глубинах 3 и 4 дополнительно
использовался штраф за отклонение числа теорем с новой точкой от 2 и 1.
Проверка Extending имела лимит 1500 мс на задачу; включены стандартные
проверки и независимая проверка истинности.

В этих двух запусках requireNonLocalTheorem=true: пруверу передавались только
конфигурации с найденным фактом, затрагивающим новую точку и точки вне её
непосредственных аргументов. В опубликованных стартовых профилях и в коде
по умолчанию это ограничение **выключено**. Оно не является общим принципом
содержательности задачи. Приведённые результаты относятся к явно указанным

**Ограничения, влияющие на подбор.**

- Считаются только типы утверждений существующего TheoremFinder. Отсутствие
  найденных теорем не означает отсутствия геометрических свойств.
- Разные утверждения на одной многоточечной прямой/окружности считаются
  отдельно. Плотность может возрастать из-за таких повторяющихся связей.
- Нулевая степень новой точки на последней глубине не даёт нового факта,
  но такая ветвь может занять место среди keep из-за общей формулы стоимости.
- Поиск сохраняет ограниченное число ветвей. Сброс истории при MaxVisited
  допускает повторные посещения. Воспроизводимый checkpoint дерева не сделан.
- Оптимальные параметры и расписание целей не найдены; они оставлены
  настраиваемыми. Измерение числа теорем не удостоверяет сложность задачи.
- Дополнительные условия в исходную конфигурацию не вводятся.
