# Старый эксперимент: короткие совместные связи

Для нового C#-поиска используйте [THEOREM_SEARCH.md](THEOREM_SEARCH.md).
Этот файл описывает более ранний отдельный эксперимент с Python.

Режим выключен по умолчанию. Это исследовательская эвристика, не оценка
доказанной сложности и не гарантия роста красоты/новизны задач.

Модуль не содержит каталог геометрических теорем. Он берёт определения
построений из существующего каталога GeoGen, раскрывает их до 16 примитивов
и вычисляет конфигурацию на 12 независимых положениях исходного треугольника.
На самом рисунке численно ищутся коллинеарность, общая окружность,
параллельность, перпендикулярность, равенства длин и короткие рациональные
отношения квадратов длин. Добавляется ограниченное число пересечений
несущих прямых, которые уже есть внутри определений. Объекты, специально
построенные из сравниваемых выходов, не служат бесплатным объяснением.

Также проверяются короткие тождества вычисляемых преобразований: например,
возвращается ли исходная точка после повторения того же построения в простой
фиксированной опорной геометрии. Максимум две такие пробы на запрос; список
названий инволюций не записан в модуле. Сложная обёртка может численно
совпасть с более простым промежуточным объектом; для эвристики выбирается
это короткое представление. Исходные определения и теоремы не переписываются.

Общая прямая/окружность учитывается сильнее совпадения отдельных числовых
характеристик. Семейства свидетельств насыщаются: сто записей одного
равенства не увеличивают силу в сто раз. Весам пока нет экспертной калибровки.
Не найденная короткая связь означает только отсутствие свидетеля в текущем
ограниченном языке. Это не доказательство человеческой несвязанности.

Например, две проекции одного объекта на прямые, имеющие точку пересечения,
автоматически связываются общей окружностью. Никаких названий точек
или заранее записанных свойств этой конфигурации для этого не требуется.
Группы принадлежащих одной окружности точек объединяются численно.

## Выбор построений внутри GeoGen

Для сохранённого исходного архива старого эксперимента:

```bash
tar -xzf GeoGen-Setuper-relations.tar.gz
cd GeoGen-Setuper-relations
bash build.sh deps  # если системные зависимости ещё не установлены
bash build.sh build --output ./dist/geometry-suite-relations --test
```

Можно использовать старый кэш через `--state /путь/к/старому/.builder`.
Сборщик сам получает закреплённые исходники и применяет 13 патчей.
Новый комплект собирается в отдельный каталог. После сборки:

```bash
./dist/geometry-suite-relations/geometry-suite run ./story.txt \
  --output ./runs/relations-001 \
  --experimental-relations --relation-target 0.2 \
  --relation-proposals 24 --relation-keep 6 --relation-seed 17 \
  --standard-checks --quality-checks --view
```

На каждом шаге генерации отдельно выбирается ограниченная порция операций
и аргументов, затем возвращаются несколько продолжений. Все сочетания
аргументов не перечисляются. Родительские симметрии учитываются до отбора;
часть мест сохраняет разнообразие операций. После выбора обычный C#-конструктор,
симметрийный фильтр и остальные проверки решают геометрическую допустимость.
Один долгоживущий Python-worker обслуживает процесс GeoGen. В нём кэшируются
вычисленные объекты и профили; скрытые точки исключены из новых аргументов.

`relation-target` — желаемый условный уровень совместных свидетельств
**между аргументами следующего построения**, от 0 до 1. Это не доля плохих
точек и не вероятность сложности. Для изменения структуры полезно сравнивать
0, 0.2 и 0.5. Стартовый треугольник сам по себе ещё не даёт разных аргументных
групп; различия появляются при дополнении конфигурации.

Контрольный режим с теми же ограничениями числа предложений:

```bash
./dist/geometry-suite-relations/geometry-suite run ./story.txt \
  --output ./runs/uniform-001 --experimental-relations \
  --relation-policy uniform --relation-proposals 24 --relation-keep 6
```

В geogen.log сохраняются строки RELATION_SAMPLER: число предложений,
оставленные действия, их оценки, время и возможный отказ модели.
Кандидаты неизвестного покрытия могут идти в ограниченную случайную
разведку, но отсутствие правил не начисляет им оценку злобности.

Первая реализация поддерживает Triangle/RightTriangle и выбирает только
операции Point ← Point,…,Point. Остальные операции пользовательского списка
в этом экспериментальном режиме не перебираются. Внутренний обход остаётся
DFS выбранных продолжений; полного планирования гипотез и фронтира здесь нет.
Команда discover пока не включает этот режим. Нужны новые каталоги output.
Файл исходного сюжета не меняется.

## Посмотреть связь и группы

```bash
./dist/geometry-suite-relations/geometry-suite experimental-relations ./story.txt --pair P Q
./dist/geometry-suite-relations/geometry-suite experimental-relations ./story.txt \
  --all-pairs --pair-budget 24
```

Отчёт содержит найденные свидетельства, короткие вспомогательные построения,
каналы связи и границы перебора. Прямого обращения к пруверу в этой оценке нет.
Сам отчёт не участвует в отбраковке готовой задачи как доказанно тривиальной.

Для отдельного эксперимента с начальным префиксом:

```bash
./dist/geometry-suite-relations/geometry-suite experimental-sample ./story.txt \
  --output ./runs/prefix-001 --steps 2 --max-depth 4 --target-strength 0.2
```

Получается обычный sampled.txt. Добавленные точки вычитаются из оставшихся
лимитов, глубина ограничивается явно. Это отдельный режим подготовки входа;
флаг run выше работает непосредственно внутри дальнейшего поиска.

Из исходников эти команды доступны через `python3 runtime.py`; требуется
`--catalog ПУТЬ_К_КАТАЛОГУ_СОБРАННОГО_КОМПЛЕКТА` для двух аналитических команд.
Новые Python-модули используют только стандартную библиотеку.

## Откат

Убрать `--experimental-relations`: включается прежнее полное перечисление.
Новый sampler не вызывается. Исходный story остаётся тем же. Экспериментальные
запуски имеют отдельные output; их можно сохранить или удалить отдельно.
Модули и C#-патч не заменяют прежние проверяющие и не переписывают старые задачи.
Сборка проверяет соответствие флага и DLL по маркеру SHA-256, чтобы старый
бинарник не мог молча проигнорировать новый режим.
